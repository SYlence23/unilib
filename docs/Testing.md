# Фінальне тестування

Документ описує, як перевірено UniLib перед здачею: автоматичні тести, покриття коду
і сценарії ручної перевірки інтерфейсу.

## Як запустити

```powershell
dotnet test unilib.slnx --configuration Release --collect "XPlat Code Coverage" --results-directory TestResults
```

Тести працюють із SQLite у пам'яті, тому PostgreSQL для них не потрібен.
На кожен PR і push у `main` ті самі тести запускає CI ([CI.md](CI.md)), а підсумок
покриття потрапляє на сторінку запуску в GitHub Actions.

## Покриття коду

Без EF-міграцій і згенерованих файлів.

| Шар | Рядки | Гілки |
|---|---:|---:|
| Сервіси (`Services/`) — бізнес-логіка | **90 %** (482 / 535) | **92 %** (154 / 168) |
| Доступ до даних (`Data/`) | 91 % (159 / 175) | 70 % (7 / 10) |
| Моделі (`Models/`) | 79 % (67 / 85) | 100 % (4 / 4) |
| Допоміжний код UI (`CatalogData`, `ErrorMessages`, `Ui`, `Theme`, `Icons`) | 27 % (82 / 300) | 37 % (37 / 101) |
| Форми й екрани (`UI/Forms`, `UI/Controls`) | 0 % | 0 % |
| **Усього** | **30 %** (819 / 2765) | **30 %** (207 / 687) |

Бізнес-правила (ліміти, статуси, перевірка вводу, безпека входу) зосереджені в сервісах,
і вони покриті майже повністю. Форми WinForms автоматичними тестами не покриваються:
вони потребують запущеного вікна. Їх перевіряють сценарії ручного тестування нижче.
`CatalogData` та `ErrorMessages`, які містять логіку екранів, винесено з форм саме для того,
щоб їх можна було тестувати (покриття 97 % і 96 %).

Не покриті тестами `FacultyService` і `RoleService`: це прості довідники лише з читанням.

### Виправлено під час фінального тестування

- **Покриття не рахувалося.** CI завжди показував «No assemblies have been covered»:
  `coverlet.collector` 6.0.4 не міг інструментувати `unilib.dll`, бо не знаходив збірки
  Windows Desktop. Після оновлення до 10.1.1 покриття рахується.
- **Повторна заявка на ту саму книгу.** Заборону перевіряв лише екран каталогу, і то за
  завантаженими раніше даними. Із застарілого екрана чи з другого вікна можна було створити
  дублікат. Тепер це правило перевіряє `ReservationService`, тест додано.
- Додано 15 тестів для `AuthorService` і `CategoryService` (покриття було 47 % і 35 %, стало 100 %).

## Відомі обмеження

- **Видача й повернення книг немає в інтерфейсі.** `LoanService` вміє видавати, повертати
  й позначати прострочені позики (покрито тестами), але екрана для бібліотекаря ще немає.
  Затверджена заявка лишається в статусі «Approved».
- Права ролей перевіряє інтерфейс, а не сервер: застосунок підключається до БД напряму
  (ризик №12 у [Security.md](Security.md)).
- Немає блокування після кількох невдалих спроб входу (ризик №10).
