## 1. Мета етапу

Визначити стратегію тестування системи **UniLib**, створити автоматизовані модульні та інтеграційні тести, перевірити крайові ситуації й виконати рефакторинг проблемних ділянок коду.

---

## 2. Стратегія тестування

| Що | Як | Чому |
|---|---|---|
| **Бізнес-логіка** (сервіси) | Модульні тести xUnit | Правила видачі, бронювання та авторизації — найважливіша частина системи |
| **Робота з базою** | Інтеграційні тести на реальному EF Core + SQLite у пам'яті | Перевіряються справжні запити, зовнішні ключі й CHECK-обмеження |
| **Схема бази** | Тест відповідності моделі й міграцій (Npgsql) | Ловить зміни моделі, для яких забули створити міграцію |
| **Інтерфейс** | Ручна перевірка + тести логіки екрана каталогу (`CatalogData`) | Логіку винесено з форм, щоб її можна було тестувати |

Принципи:

- **Ізоляція.** Кожен тест отримує власну порожню базу в пам'яті (`TestDb`), яка зникає після тесту.
- **Детермінованість.** Замість системного годинника використовується фіксована дата (`FixedTime`, 10.03.2026), тому тести з датами дають той самий результат будь-якого дня.
- **Структура AAA.** Кожен тест має три кроки: підготувати дані → викликати метод → перевірити результат.
- **Таблиці випадків.** Для правил із багатьма варіантами використовується `[Theory]` з набором вхідних даних.
- **Тести разом із кодом.** Кожен pull request супроводжується тестами, і перед злиттям тести прогоняються.

### 3.1. Інтеграційні тести

- `LibraryServiceTests.Database_*` записують дані напряму в базу, оминаючи сервіс, і перевіряють, що **сама база** відхиляє неправильні координати через CHECK-обмеження.
- `BookServiceTests.AddWithAuthors_FailedSave_*` перевіряють, що при помилці зовнішнього ключа в базі не лишається частково збережених даних.
- `DatabaseSetupTests` перевіряють, що стара база, створена без міграцій, коректно отримує історію міграцій.
- `ModelTests.Migrations_MatchTheModel` використовує справжню конфігурацію Npgsql і падає, якщо модель змінено без міграції.

## 4. Приклади перевірки крайових ситуацій

**Межові значення координат.** ±90 і ±180 приймаються, а значення 90.000001 уже відхиляється:

```csharp
[Theory]
[InlineData("90.000001", "0", "Latitude")]
[InlineData("-90.000001", "0", "Latitude")]
[InlineData("0", "180.000001", "Longitude")]
[InlineData("0", "-180.000001", "Longitude")]
public async Task Create_OutOfRange_Throws(string latitude, string longitude, string field)
```

**Дати.** Видача з датою повернення «сьогодні» або в минулому відхиляється. Видача з терміном «сьогодні» не вважається простроченою, а з терміном «вчора» — вважається:

```csharp
[Theory]
[InlineData(0)]
[InlineData(-3)]
public async Task Create_DueDateNotAfterToday_Throws(int days)
```

**Ліміти.** Видача шостої книги відхиляється. Повернені книги до ліміту не рахуються. До ліміту бронювань рахуються й підтверджені запити, а скасовані й завершені — ні.

**Усі переходи статусів бронювання.** Таблиця 4 статуси × 4 дії = 16 випадків. Для заборонених переходів додатково перевіряється, що статус не змінився:

```csharp
{ ReservationStatus.Pending,   Action.Confirm,  ReservationStatus.Active },
{ ReservationStatus.Completed, Action.Reopen,   null },  // null = відмова
```

**Регістр і кирилиця.** «robert MARTIN» знаходить існуючого автора «Robert Martin», « programming » — категорію «Programming», «ПОЕЗІЯ» — «Поезія». Дублікат email з іншим регістром не реєструється.

**Безпека адміністратора.** Якщо хтось зареєстрував `admin@unilib.com` зі своїм паролем, цей акаунт **не** отримує прав адміна.

**Помилки збереження.** Якщо збереження книги впало, в базі не лишається нових категорій чи авторів, а повторна спроба проходить успішно.

## 5. Приклади виконаного рефакторингу

| Проблема | Рефакторинг |
|---|---|
| Сервіси брали дату з системного годинника, тому правила з датами не можна було перевірити | `LoanService` і `ReservationService` приймають `TimeProvider`; у тестах передається `FixedTime` |
| Логіка створення адміністратора жила в `Program.cs`, де її не можна протестувати | Перенесено в `AuthService.EnsureAdminAsync`, додано 4 тести |
| Екран каталогу сам ходив у базу | `CatalogData` приймає фабрику бази, тож його логіку перевіряють тести |
| Додавання книги зберігало категорію, авторів і книгу окремо; при помилці лишалося «сміття», а повторна спроба падала | Усе зберігається одним `SaveChanges`; додано регресійний тест |
| Порівняння назв у SQL через `lower()` залежало від локалі PostgreSQL і не працювало з кирилицею | Назви порівнюються в C# через `OrdinalIgnoreCase` |
| Кожен тест вручну створював користувачів, книги, видачі | Спільні хелпери `TestData` (`AddBook`, `AddUser`, `AddLoan`, `AddReservation`) |
| Ліміти видачі й бронювань (`LibraryRules`) лежали в UI-файлі `CatalogData.cs`, тож сервіси не могли їх застосувати | `LibraryRules` перенесено в шар сервісів, і `LoanService` тепер сам перевіряє ліміт |

## 6. Демонстрація запуску тестів

Запуск з командного рядка:

```bash
dotnet test unilib.Tests/unilib.Tests.csproj
```

Результат:

```
Passed!  - Failed: 0, Passed: 109, Skipped: 0, Total: 109, Duration: 8 s - unilib.Tests.dll (net10.0)
```

У Visual Studio тести запускаються через **Test → Test Explorer → Run All Tests** (`Ctrl+R, A`).

Детальний опис кожного тестового файлу наведено в [Tests.md](./Tests.md).

## 7. Відомі обмеження

- Тести працюють на SQLite, а застосунок — на PostgreSQL. Частину поведінки (наприклад, пошук кирилицею через SQL) тести не бачать. Наступний крок — інтеграційні тести на справжньому PostgreSQL (Testcontainers).
- Сервіси `AuthorService`, `CategoryService`, `FacultyService`, `RoleService` поки без тестів.
- `FavoriteService` і `CatalogData` ще беруть дату з системного годинника.

## 8. Висновки

1. Визначено стратегію тестування: модульні тести бізнес-логіки, інтеграційні тести роботи з базою та перевірка відповідності схеми міграціям.
2. Кількість автоматизованих тестів зросла з 51 до 109. Усі тести проходять.
3. Перевірено крайові ситуації: межові значення, дати, ліміти, усі переходи статусів, регістр і кирилицю, помилки збереження.
4. Виконано рефакторинг проблемних ділянок, щоб код став тестованим (`TimeProvider`, `EnsureAdminAsync`, `CatalogData`), і виправлено знайдені помилки.
