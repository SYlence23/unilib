## 1. Створення необхідних UML-діаграм

Для опису структури та функціональності системи автоматизації університетської бібліотеки було визначено основні сутності предметної області та взаємодію користувачів із системою.

### 1.1. Модель даних

Для системи було визначено основні сутності:

- Role — роль користувача;
- Faculty — факультет;
- User — користувач системи;
- Library — бібліотека;
- Category — категорія книги;
- Author — автор;
- Book — книга;
- BookAuthor — зв'язок між книгами та авторами;
- Copy — конкретний примірник книги;
- Loan — видача книги;
- Reservation — бронювання книги;
- Favorite — обрані книги користувача.

Дана модель описує структуру даних бібліотеки та зв'язки між основними сутностями системи.

### 1.2. UML-діаграма варіантів використання

Для визначення функціональних можливостей системи та взаємодії з користувачами використовується UML-діаграма варіантів використання.

Основними користувачами системи є:

- Студент;
- Бібліотекар;
- Адміністратор.

**Студент може:**
- увійти до системи;
- переглядати каталог книг;
- шукати книги;
- шукати книгу за факультетом;
- переглядати інформацію про книгу;
- додавати книгу до обраного;
- бронювати книгу;
- переглядати свої бронювання;
- переглядати власні видачі.

**Бібліотекар може:**
- увійти до системи;
- переглядати книги;
- шукати книги;
- переглядати читачів;
- видавати книги;
- приймати повернення книг;
- переглядати інформацію про видачі;
- працювати з бронюваннями;
- підтверджувати/відхиляти бронювання;
- перегляд запитів на бронювання.

**Адміністратор може:**
- керувати користувачами;
- керувати ролями;
- керувати книгами;
- керувати авторами;
- керувати категоріями;
- переглядати інформацію про бібліотеку.

## 2. Опис основних сценаріїв

На основі функціональних можливостей системи було визначено основні сценарії її використання.

### 2.1. Реєстрація користувача

**Актор:** користувач.
**Передумова:** користувач не має облікового запису.

**Основний сценарій:**
1. Користувач відкриває сторінку реєстрації.
2. Вводить ім'я, електронну пошту та пароль.
3. Система перевіряє правильність введених даних.
4. Система перевіряє, чи не існує користувач із такою електронною поштою.
5. У разі успішної перевірки створюється новий обліковий запис.
6. Користувач отримує повідомлення про успішну реєстрацію.

**Результат:** новий користувач зареєстрований у системі.

### 2.2. Авторизація користувача

**Актор:** студент або бібліотекар.

**Основний сценарій:**
1. Користувач відкриває сторінку авторизації.
2. Вводить електронну пошту та пароль.
3. Система перевіряє введені дані.
4. У разі правильних даних система виконує авторизацію.
5. Користувач отримує доступ до функцій відповідно до своєї ролі.

**Результат:** користувач або бібліотекар авторизований у системі.

### 2.3. Перегляд каталогу книг

**Актор:** студент

**Основний сценарій:**
1. Користувач відкриває каталог.
2. Система отримує список книг із бази даних.
3. Система відображає назву, автора та іншу основну інформацію.
4. Користувач переглядає доступні книги.
5. Користувач може перейти до детальної інформації про вибрану книгу.

**Результат:** користувач отримує доступ до каталогу.

### 2.4. Сценарій «Запит на бронювання книг»

**Актор:** студент

**Основний сценарій:**
1. Користувач знаходить необхідну книгу.
2. Відкриває інформацію про книгу.
3. Натискає кнопку «Забронювати».
4. Система перевіряє можливість створення бронювання.
5. Система створює запит на бронювання.
6. Запиту присвоюється статус очікування підтвердження.
7. Система повідомляє користувача, що запит на бронювання успішно створено.
8. Запит передається бібліотекарю для розгляду.

**Результат:** книга заброньована для користувача.

### 2.5. Сценарій «Підтвердження бронювання бібліотекарем»

**Актор:** бібліотекар.

**Основний сценарій:**
1. Бібліотекар відкриває розділ із запитами на бронювання.
2. Система відображає список запитів, які очікують підтвердження.
3. Бібліотекар обирає необхідний запит.
4. Переглядає інформацію про користувача та книгу.
5. Перевіряє можливість виконання бронювання.
6. Натискає кнопку «Підтвердити».
7. Система змінює статус бронювання на підтверджений.
8. Система повідомляє користувача про підтвердження бронювання.

**Результат:** бронювання підтверджене бібліотекарем і користувач може отримати книгу відповідно до правил бібліотеки.

### 2.6. Сценарій «Відхилення бронювання бібліотекарем»

**Актор:** бібліотекар.

**Основний сценарій:**
1. Бібліотекар відкриває список запитів на бронювання.
2. Обирає необхідний запит.
3. Перевіряє інформацію про книгу та користувача.
4. Встановлює, що бронювання неможливо виконати.
5. Натискає кнопку «Відхилити».
6. Система змінює статус запиту на відхилений.
7. Система повідомляє користувача про результат розгляду.

**Результат:** запит на бронювання відхилений бібліотекарем.

### 2.7. Перегляд власних бронювань

**Актор:** користувач.

1. Користувач відкриває особистий кабінет.
2. Переходить до розділу «Мої бронювання».
3. Система отримує його бронювання.
4. Відображається список бронювань.
5. Для кожного бронювання відображається його поточний статус.

**Результат:** користувач бачить свої бронювання та їхні статуси.

### 2.8. Сценарій «Видача книги»

**Актор:** бібліотекар.
**Передумова:** бронювання користувача було підтверджене.

1. Користувач звертається до бібліотеки.
2. Бібліотекар знаходить підтверджене бронювання.
3. Перевіряє дані користувача.
4. Видає книгу користувачу.
5. Система змінює статус книги на «Видана».
6. Створюється запис про видачу книги.

**Результат:** книга видана користувачу.

### 2.9. Сценарій «Повернення книги»

**Актор:** бібліотекар.

**Основний сценарій:**
1. Бібліотекар знаходить активну видачу.
2. Вибирає потрібний запис.
3. Система визначає книгу та користувача.
4. Бібліотекар підтверджує повернення.
5. Система записує дату повернення.
6. Статус видачі змінюється.
7. Статус примірника книги змінюється на доступний.

**Результат:** книга повернена до бібліотеки.

### 2.10. Сценарій «Додавання книги»

**Актор:** адміністратор або бібліотекар.

**Основний сценарій:**
1. Користувач із відповідними правами відкриває розділ книг.
2. Натискає «Додати книгу».
3. Вводить інформацію про книгу.
4. Обирає категорію, автора та бібліотеку.
5. Система перевіряє введені дані.
6. Система зберігає інформацію.
7. Нова книга з'являється в каталозі.
